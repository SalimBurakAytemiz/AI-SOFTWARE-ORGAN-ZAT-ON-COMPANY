Caching & revalidation

Public pages are static + ISR with a revalidate safety net; the primary freshness mechanism is on-demand revalidation — every successful admin write calls revalidateContent(entity, id?), which fires the right tags (projects, project:{slug}, sitemap, per-module tags). Admin is force-dynamic, no-store, never indexed.

Environments & secrets

Three environments — local, staging (Supabase staging), production (Supabase prod, prepared not deployed). Secrets (SUPABASE_SERVICE_ROLE_KEY, MAIL_PROVIDER_API_KEY, REVALIDATE_WEBHOOK_SECRET) live only in Vercel encrypted env + git-ignored .env.local; never in a NEXT_PUBLIC_* name; gitleaks in CI; the service-role client is an isolated server module an ESLint rule + a bundle test forbid importing anywhere else.

Translation strategy

Base row = locale-neutral facts; *_translations keyed by (parent_id, locale). Per-locale translation_status lets the owner publish EN while TR is still draft. Fallback → site_settings.default_locale. UI chrome lives in next-intl catalogs, not the DB. Slugs are locale-neutral.

Publication strategy

Public read predicate = status='published' AND visible=true, enforced by RLS. Transitions (publish / unpublish / hide / archive / restore) are transactional RPCs that each write one content_audit row and revalidate. Archive ≠ delete.

RLS strategy

  • RLS enabled on every table in public. Default deny.
  • Base tables: select where published+visible OR is_admin(). Child/translation tables gate on the parent's publication state.
  • All writes: USING (is_admin()) WITH CHECK (is_admin()).
  • contact_messages: anon INSERT only; admin SELECT/UPDATE; a BEFORE INSERT trigger caps inserts per ip_hash/hour.
  • content_audit: admin INSERT+SELECT only → append-only. admin_users: not app-editable.
  • An automated {role × op × row-state} test matrix is a release gate; a new table with no matrix entry fails CI.

QA visual language

The recurring vocabulary that makes the site legibly "a QA engineer's": monospace type · PASS/FAIL pills · coverage meters · scenario tables · bug cards with severity rails · request/response code blocks · SQL blocks · status dots · "evidence" chips · terminal snippets · diff highlights. "/admin is hidden" ≠ "/admin is secure." Every protection is enforced at the layer that owns the data.

Draft / unpublished contentdisclosure via wrong query, direct URLRLS status='published' AND visible on every read; notFound() for misses

Admin sessiontheft, fixation, CSRFHttpOnly/Secure/SameSite=Lax, PKCE, origin check on mutations, MFA/TOTP
